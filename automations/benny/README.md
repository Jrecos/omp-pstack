# benny

benny gives you two OMP-native automations for slack issue reports. one triages each report. the other reproduces confirmed bugs and may prepare a small draft fix.

the files in this directory are dormant setup and automation sources. they do not appear as slash skills.
`pstack` commands below are run through the installed-root launcher `bun "$PSTACK_ROOT/src/cli.ts" ...`: resolve `PSTACK_ROOT` once with the install resolver in the omp-pstack README (`running the pstack CLI after install`; inside the package checkout, `PSTACK_ROOT="$(pwd)"`). a marketplace install does not put `pstack` on PATH.

## set it up

1. install the pack into the target repository: run `bun "$PSTACK_ROOT/src/cli.ts" benny setup --target <repo>`. setup merges this whole directory into the target at `.omp/automations/benny/` and installs the omp-pstack plugin at project scope (`omp plugin marketplace add` plus `omp plugin install --scope project omp-pstack@omp-pstack`) so shared skills such as `how`, `why`, `tdd`, and `unslop` resolve in fresh target sessions. destination-only files are preserved and differing managed files are reported for review, never blind-overwritten.
2. keep user-owned configuration outside the copied pack: copy [`configuration.example.yaml`](./templates/configuration.example.yaml) to `.omp/benny/configuration.yaml` and [`feature-map.example.md`](./skills/reproduce-and-fix-issues/references/feature-map.example.md) to `.omp/benny/feature-map.md`, then fill them. copy [`routing.example.md`](./skills/triage-issue-reports/references/routing.example.md) to `.omp/benny/routing.md` and set `routing.map_path` to it: the routing map is required and committed, but it may be an empty map (no routes, empty fallback) when no owner routing is wanted. keep secret values in environment variables named by the config, never in YAML.
3. commit the `.omp` declarations before enabling anything: `.omp/plugins/installed_plugins.json`, `.omp/plugins/omp-plugins.lock.json`, `.omp/automations/benny/`, and every referenced secret-free configuration file.
4. run preflight: `bun "$PSTACK_ROOT/src/cli.ts" benny check --config .omp/benny/configuration.yaml`. every check except `canary` must pass.
5. run a canary with a harmless test report in your configured test targets: `bun "$PSTACK_ROOT/src/cli.ts" benny canary --config .omp/benny/configuration.yaml --event <test-report.json>`. a canary is required for the exact current configuration hash and repository revision before `enable` succeeds.
6. rerun preflight with the canary recorded: `bun "$PSTACK_ROOT/src/cli.ts" benny check --config .omp/benny/configuration.yaml`. every check must now pass, including `canary`. then enable: `bun "$PSTACK_ROOT/src/cli.ts" benny enable --config .omp/benny/configuration.yaml`. background admission stays disabled until this succeeds.
enablement is authoritative only in profile-private runtime state (mode-0600 files outside the repo); repository-local files never enable anything, and the default is disabled. private runtime state under `.omp/pstack/state/` is anchored in the repository's `.git/info/exclude` through `git rev-parse --git-path info/exclude` and proven with `git check-ignore`, so it can never leak into a commit regardless of the repo's own `.gitignore`.
7. trigger reports through one of the two supported transports: the external CLI (`bun "$PSTACK_ROOT/src/cli.ts" benny run --config .omp/benny/configuration.yaml --event <json-file|->`, given a Slack Events API envelope by a trusted local caller) or Slack Socket Mode (`runtime.trigger: "socket-mode"` in the config, served by the native runner).
8. verify thread safety: send a harmless test report and confirm every source-channel post stays in the original thread and no root message appears.
9. keep evidence retention honest on a quiet host: the runner sweeps expired evidence at startup and while runs settle, but if events stop coming, schedule the one-shot sweep externally (cron or a systemd timer, hourly is plenty): `bun "$PSTACK_ROOT/src/cli.ts" benny sweep --config .omp/benny/configuration.yaml`. evidence past `control.artifact_retention_hours` is removed unless a queued/running run owns it; the sweep deletes nothing when ownership cannot be established.
